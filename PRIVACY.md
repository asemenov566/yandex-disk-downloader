# Данные и доступ

Расширение обращается к Яндекс Диску по публичной ссылке, которую вы открыли или вставили. Ссылка задаёт область обработки: выбранный каталог и вложенные папки. Доступ к остальному личному Диску не запрашивается.

Для работы используются API cloud-api.yandex.net, downloader.disk.yandex.ru и файловые серверы storage.yandex.net. Яндекс получает обычные запросы на чтение файлов и их списков. Расширение не содержит аналитики, рекламы и внешнего сервера разработчика.

Задания, публичные ссылки, имена, размеры, доступные контрольные суммы и идентификаторы собственных загрузок сохраняются в IndexedDB внутри профиля Chrome. Это позволяет продолжить работу и узнать ранее скачанные файлы.

Разрешение activeTab используется при нажатии значка, чтобы прочитать адрес текущей вкладки. Содержимое вкладок, не относящихся к запущенным заданиям, пароли и cookies расширение не читает. Разрешение downloads сохраняется для восстановления состояния загрузок старых версий. Новые файлы записываются через доступ к выбранной пользователем папке. Фоновый документ нужен для обработки изображений и работы после закрытия всплывающего окна.

При первом скачивании пользователь выбирает папку и разрешает чтение и запись. Дескриптор доступа сохраняется локально в IndexedDB. Расширение проверяет ожидаемые имена и размеры файлов внутри её yandex-disk или vk-messager и сохраняет новые файлы туда же. Содержимое локальных файлов не отправляется на сервер. Пересчёт хеша уже сохранённого файла не выполняется. При отзыве разрешения очередь приостанавливается до нового подтверждения доступа.

Удаление расширения очищает его кэш в профиле Chrome. JSON-база и скачанные файлы остаются в выбранной папке; выбор этой папки после переустановки восстанавливает задания и историю. Публичные ссылки управляются на стороне Яндекс Диска; удаление расширения не отключает их.

Настройки сохраняются в JSON-базе и локальном кэше IndexedDB. Удаление задания из меню настроек не удаляет файлы и историю сохранений.

Разрешение power предотвращает автоматический сон системы только при активной очереди; экран может выключаться. Разрешение alarms используется для периодической проверки фонового обработчика без действий пользователя в браузере. Эти функции не читают содержимое вкладок и не отправляют данные разработчику.


В выбранной папке создаётся yandex-disk/downloader-state.json с публичными ссылками, именами и путями файлов, прогрессом, ошибками, историей сохранений, настройками, версией расширения и версией формата. Это обычный локальный JSON без шифрования; он не отправляется разработчику. При миграции рядом сохраняется исходная копия downloader-state.before-migration-….json. Дескриптор разрешения папки и идентификаторы скачиваний Chrome не переносятся в JSON.

## Диалоги ВК

Разрешение scripting и доступ к vk.ru/vk.com нужны для чтения названия выбранного диалога и выполнения запроса messages.getHistoryAttachments в авторизованной вкладке. Используется только peer_id запущенного задания. Токен текущей веб-сессии используется внутри вкладки для обращения к web.api.vk.ru; расширение не получает его в ответе, не пишет в файлы, IndexedDB или журналы. Cookies не считываются расширением; браузер сам применяет текущую сессию при запросе.

Фото загружаются с разрешённых доменов vkuserphoto.ru, vkuserphoto.com, userapi.com, vkusercontent.ru. В локальной базе сохраняются название/ссылка диалога, идентификаторы фотографий и позиции вложений, ссылки на оригиналы/превью, пути файлов и прогресс. Текст сообщений, профили, access_key и web_view_token не возвращаются из вкладки обработчику расширения. JSON не зашифрован; ссылки на фотографии могут предоставлять доступ к соответствующему фото, поэтому базу следует хранить приватно.

ВК не сообщает размер оригинала в байтах. Существующий файл по устойчивому имени photoOWNER_ID_ID проверяется декодированием изображения; это защищает от пустого/повреждённого файла, но не доказывает совпадение содержимого с сервером.

### Видео и запуск из диалога (1.4.2)

Внутри вкладки дополнительно выполняется messages.getHistory с count=1 для начального номера сообщения. Имена участников для видеофильтра не запрашиваются. Текст сообщения не возвращается расширению. Названия видео и позиции обоих списков сохраняются в локальной базе. Старый список разрешённых имён удаляется при восстановлении задания. Скачиваются только MP4 с разрешённых серверов ВК, в том числе okcdn.ru и vkuser.net; внешние плееры игнорируются. Существующие MP4 проверяются по заголовку контейнера, что не является полной проверкой содержимого; при загрузке дополнительно проверяется Content-Length, если он доступен.

При восстановлении сессии расширение может перезагрузить выбранную вкладку диалога и повторить запрос. Закрытые вкладки и вкладки с другим диалогом не перенаправляются. Токен остаётся внутри страницы.

Для расчёта времени в локальной базе сохраняются интервалы активности заданий и количество новых сохранений. Эти данные не отправляются на сервер.

## Необязательный журнал диагностики

Галочка «Логирование» выключена по умолчанию. При включении события дописываются каждые 5 секунд в ежедневный файл log--дд-мм-гггг.log рядом с downloader-state.json в выбранной папке / yandex-disk: идентификатор и название сессии, номер файла в очереди, тип и этап операции, счётчики, коды ошибок, длительности ожидания, hostname файлового сервера и факт изменения ссылки после обновления. Полные URL, токены, тела API-запросов и ответов, содержимое файлов и переписки не записываются. Журнал не переносится в JSON-базу альбомов и не отправляется разработчику. В базе браузера журнал не хранится; старая запись debug-log удаляется при обновлении. В оперативной памяти временно ожидают записи не более 20 000 событий; при недоступной папке настройки показывают ошибку и число потерянных событий при переполнении. «Скачать копию лога» выгружает сегодняшний файл, «Очистить лог за сегодня» очищает только его. Выключение записи сохраняет накопленные события для диагностики.

Кнопка «Обновить все вкладки ВК» перечисляет открытые вкладки vk.ru/vk.com и перезагружает их, без чтения переписки и переключения фокуса.

## Даты файлов

Метаданные новых фотографий обрабатываются локально в выделенном потоке расширения. ExifTool/WebAssembly включён в пакет; код с CDN не загружается, фотографии сторонним сервисам не передаются. Native Messaging и отдельная программа не используются.

Даты источников сохраняются в общем `yandex-disk/downloader-dates.json` и в отдельных `downloader-dates.json` по папкам. Записи содержат публичную ссылку/адрес диалога, путь вложения, дату, источник даты и локальные имена; токенов и прямых ссылок на медиа нет. `downloader-date-results.json` содержит подтверждения изменённого размера и контрольные суммы обработанных фотографий для исключения повторных копий. Эти файлы остаются в выбранной папке и никуда не отправляются.
