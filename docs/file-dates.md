# Даты новых фотографий

С версии 1.5.13 помощник и его установка не нужны. Новые фотографии обрабатываются
в расширении перед сохранением. Исходный файл сначала проходит обычные проверки
размера/контрольной суммы, после чего локальный ExifTool в WebAssembly дополняет
метаданные без перекодирования. Запись не требует дополнительных настроек.

Существующие корректные даты EXIF, XMP и IPTC сохраняются. Недостающие даты съёмки
и создания внутри файла заполняются имеющейся датой медиа, а при её отсутствии:

- ВК: `photo.date`, затем `item.date`;
- Яндекс: `created`.

Дата загрузки используется как запасная дата, а не доказанная дата съёмки.
Часовой пояс даты источника переводится в местное время браузера с записью
смещения в EXIF. Имеющиеся даты камеры сохраняют своё время и смещение.

Обрабатываются новые оригиналы и preview. Уже существующие файлы не изменяются.
Видео пока не переписываются, но их `video.date`/`item.date` и даты Яндекса
сохраняются для внешнего скрипта. Системную дату создания Windows расширение
не устанавливает: записываются поля внутри фотографии.

## Форматы и ошибки

Проверены JPEG, PNG, TIFF, WebP, GIF (XMP) и AVIF. Для остальных форматов используется
поддержка встроенного ExifTool. BMP/ICO не поддерживают нужные поля. Фотографии
больше 128 МиБ не обрабатываются в WASM, чтобы ограничить расход памяти.

Если дата отсутствует, формат не поддерживается или проверка метаданных не проходит,
скачанный исходный файл сохраняется без изменений. В настройках показаны счётчики
обработки, отсутствующих дат, неподдерживаемых файлов и ошибок. Это не выдаётся
за успешную запись даты. При ошибке авторизации/429 получения метаданных действуют
обычные ограничения скачивания. Обработка фотографий последовательная в отдельном
worker и может занять дополнительное время; интерфейс остаётся доступным.

## JSON рядом с файлами

Общий `photo_downloader_smnv/downloader-dates.json` сохраняется независимо от записи EXIF.
Параллельно в каждой папке назначения ведётся собственный `downloader-dates.json`.
Например, `photo_downloader_smnv/vk-messeger/Название диалога/downloader-dates.json` содержит только
вложения этой папки. Вложенные папки Яндекса получают отдельные файлы.

Оба формата имеют `schema: 1`, `rootId` и объект `dates`. Ключ записи — JSON-массив
из URL источника и пути вложения. Значение содержит `date` (ISO 8601 UTC) и `source`
(`vk.photo.date`, `vk.video.date`, `vk.item.date`, `yandex.created`). В файле папки
добавляются `folder`, локальное имя `local` у записи и список фактически сохранённых
имён `saved`, включая preview. Это позволяет обрабатывать папку без чтения общей базы.
Прямых медиа-ссылок, токенов и текстов сообщений в этих JSON нет.

Даты записываются при ответах API; простой повтор скачивания по старому кешу не
создаёт отсутствующую дату. Для нового фото без встроенной или сохранённой даты
расширение дополнительно запрашивает метаданные источника. Старые коллекции
автоматически не обходятся и не мигрируются.

`photo_downloader_smnv/downloader-date-results.json` хранит подтверждения изменения размера
после EXIF: идентификатор источника, исходный размер/хеш, итоговый размер/хеш и
время изменения. Благодаря этому оригинал Яндекса с добавленными датами узнаётся
при повторном запуске. Сохраняйте этот файл вместе с основной базой и фотографиями.

## Проверка разработки

`node --test tests/*.test.js` проверяет политику дат, JSON по папкам и дедупликацию.
`scripts/check-photo-dates.mjs` запускает настоящий worker в отдельном профиле Chrome
на искусственных файлах из `test-output/photo-date-fixtures`. Для него нужны Playwright
и Chrome (пути можно передать через `PLAYWRIGHT_MODULE` и `CHROME_PATH`).

Используется [@colorhythm/exiftool-wasm 1.0.4](https://github.com/colorhythm/exiftool-wasm).
Лицензии и контрольные сведения находятся в `photo_downloader_smnv/vendor/exiftool/`.

## Перенос папки загрузок

Выбирайте родительскую папку `photo_downloader_smnv`. Внутри неё лежат базы, журнал и папки `yandex-disk` и `vk-messeger`.
При ручном переносе старой коллекции перенесите общие `downloader-state*.json`, `downloader-dates.json`, `downloader-date-results.json` и журналы из прежней `yandex-disk` в `photo_downloader_smnv`. Альбомы остаются в `yandex-disk`; прежнюю `vk-messager` переименуйте в `vk-messeger` и положите рядом. Локальные JSON с датами перемещаются вместе с фотографиями.

Ключи исходных дат не содержат абсолютного пути: это ссылка источника и ID/путь вложения. Относительные пути ВК в основной базе и подтверждениях обработки дат преобразуются при чтении; старый JSON сохраняется перед преобразованием основной базы. Если обнаружена база в прежнем месте, приложение просит перенести её и не начинает новую загрузку.
