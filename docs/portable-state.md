# Переносимая база

Путь: выбранный родитель / yandex-disk / downloader-state.json.

## Формат 1

- format: yandex-disk-downloader.
- schemaVersion: 1 — версия структуры JSON, не номер релиза.
- extensionVersion: версия расширения, выполнившего запись.
- updatedAt: время последней записи в ISO 8601.
- entries: полные задания, включая каталоги, файлы, ошибки, preview и параметры повтора.
- history: пары ключ/квитанция сохранённого файла, включая алиасы контрольных сумм.
- settings: downloadLimit и timeoutSeconds.

Идентификаторы Chrome downloads и дескрипторы папок не экспортируются. При восстановлении active-файлы возвращаются в pending, wanted сбрасывается; ожидавший повтор ошибок сохраняет includePreviews. Завершённые и ошибочные результаты сохраняются.

## Обновления

Версия релиза не определяет совместимость: совместимый schemaVersion читается и после обновления расширения. При изменении структуры добавляется последовательная функция в реестр migrations в portable-state.js и увеличивается SCHEMA_VERSION. Каждый шаг должен увеличивать номер ровно на один. Неизвестная более новая версия не читается и не перезаписывается.

Поддерживается преобразование старой структуры задания version 1 в version 2: непустые файлы, ранее пропущенные фото-загрузчиком, становятся ожидающими загрузки. До преобразования записывается точная исходная копия с именем downloader-state.before-migration-<time>-<uuid>.json. Резервные копии автоматически не удаляются.

## Запись и восстановление

При запуске с доступом к папке JSON имеет приоритет над кэшем Chrome. Если JSON отсутствует, начальная копия создаётся из прежней IndexedDB. При выборе папки сначала проверяется файл и только затем заменяется очередь. Повреждённые данные не заменяются пустой базой.

Записи сериализованы и объединяют параллельные контрольные точки. Полный JSON фиксируется через createWritable/close; неудачная запись отменяется. Очередь ожидает сохранения контрольной точки перед дальнейшей обработкой. История файлов записывается вместе с очередной контрольной точкой задания. Это не журнал всех UI-действий и не гарантия сохранения незавершённой операции при аварийном выключении.

Одновременная работа нескольких независимых установок расширения с одной JSON-базой не синхронизируется. Используйте одну установку для выбранной папки. Кэш IndexedDB хранит разрешение и рабочую копию; после переустановки потребуется заново выбрать папку и разрешить доступ.


С 1.3.9 задания содержат необязательное поле runNewFiles — число успешных записей файлов за текущий запуск. Это совместимое расширение формата 1; отсутствие поля означает 0. Поле сохраняется при восстановлении и продолжении и сбрасывается при новом обходе или повторе ошибок.
