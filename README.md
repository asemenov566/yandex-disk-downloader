# Загрузчик Яндекс Диска и ВК

Фото, видео и файлы из публичных папок Яндекс Диска и вложений диалогов ВК — с сохранением на компьютер, продолжением и повтором ошибок.

[Скачать последнюю версию](https://github.com/asemenov566/yandex-disk-downloader/releases/latest) · [Установка](install.md)

## 1.5.7 — запуск после повреждения базы и резервные копии

- Повреждённый локальный кеш браузера больше не мешает открыть исправную JSON-базу в выбранной папке. Если исправных данных нет, приложение сообщает об этом без ошибки null.id и не записывает пустую базу поверх повреждённого файла автоматически.
- После записи JSON файл читается повторно и сравнивается с записанным текстом. При подключении папки сохраняется резервная копия; во время работы две копии downloader-state.backup-1.json и downloader-state.backup-2.json чередуются не чаще раза в минуту. При повреждении основной базы выбирается более новая исправная копия, а повреждённый файл сохраняется отдельно. База более новой версии автоматически не заменяется старой копией.
- Копии на том же диске не гарантируют сохранность при отказе накопителя или аварии ОС, затронувшей все копии.

## 1.5.6 — блок ссылки и пакетное обновление ВК

Автоматически подставленная ссылка раскрывает блок добавления только тогда, когда её ещё нет среди заданий. Ссылки нормализуются: диалог ВК и его раздел вложений считаются одним источником, у Яндекса учитывается путь папки. Ручное раскрытие и сворачивание сохраняются при обновлении прогресса; ручной ввод остаётся доступным.

- При обновлении ссылок ВК запрашивается до 30 вложений от точной позиции файла, с включением самого файла. Совпавшие вложения обновляют только уже известные файлы текущего диалога. Очередные запросы используют полученный ответ без повторного обращения к API. Позиции сбора списка, состав очереди и состояния скачивания не изменяются. Частота реальных API-запросов сохранена.
- В логе vk.link.refresh.batch показывает число обновлённых известных файлов, vk.request.cached — ожидание, завершившееся использованием уже полученных данных без сетевого запроса.


## 1.5.5 — восстановление вкладок и таймауты повторов ВК

- После 404 короткий таймаут получения данных больше не обрывает оставшуюся цепочку повторов. Сохранены интервалы и ожидания данных 1, 3, 6, 12, 24 и 48 секунд. Первый таймаут без предшествующей 404, отмена и другие ошибки не запускают эту цепочку. Для Яндекса ретраи 404 не включаются.
- Ожидание загрузки/восстановления вкладки ВК вынесено из общей очереди API. Одновременно восстанавливаются максимум две вкладки; обращения одного диалога используют общее восстановление. После готовности запрос возвращается в обычную последовательную очередь API с прежней паузой и сохранённой позицией.
- При уже начавшемся ручном обновлении ожидается готовность без дополнительной перезагрузки. Отмена не запускает повторный запрос вложений. События vk.recover.start/end/error позволяют отличить время восстановления от выполнения API; start.ms показывает ожидание очереди восстановления.

## 1.5.4 — очередь ВК и временные 404

- При 404 фото и видео повторно запрашиваются по прежнему URL через 1, 3, 6, 12, 24 и 48 секунд. Обновление ссылки через API выполняется только после исчерпания этих попыток. Неизменившаяся ссылка не запускает ещё один немедленный запрос. Для 401/403/410 сохранено обновление без ожидания всех повторов.
- API остаётся последовательным с прежним интервалом. При наличии обеих очередей три запроса страниц/подключения чередуются с одним обновлением ссылки. Диалоги обслуживаются по очереди; в очередь API допускается не более 16 обновлений, остальные ждут допуска. Отмена сразу удаляет ожидающие запросы.
- Ожидание ретрая или обновления ссылки освобождает поток ВК. Число одновременно обрабатываемых файлов, включая ожидающие, ограничено удвоенным выбранным лимитом отдельно для фото и видео и в сумме. Передача по-прежнему ограничена выбранными потоками; готовые повторы получают поток раньше новых файлов. При снижении лимита уже начатая работа завершается без запуска сверх нового предела.
- Лог различает освобождение/возврат потока, ожидание допуска к обновлению и выполнение API. У vk.request.start поле ms — ожидание до отправки, у vk.request.end/error — длительность выполнения запроса. У file.heartbeat enabled=false означает освобождённый поток на время ожидания.

## 1.5.3 — журнал рядом с JSON-базой

Пауза между порциями ВК: от 1 до 10 секунд с шагом 1. По умолчанию — 1 секунда.

При включённом логировании события дописываются каждые 5 секунд в `yandex-disk/log--дд-мм-гггг.log`, рядом с `downloader-state.json`. Каждый день создаётся отдельный файл; после перезапуска запись продолжается. В базе браузера журнал больше не хранится, старая запись удаляется. При недоступности папки показывается ошибка записи. Очистка журнала затрагивает только сегодняшний файл.

## 1.5.2 — фоновые ожидания, диагностика и строки сессий

- Общий прогресс сворачивается нажатием на заголовок; состояние сохраняется при обновлениях и повторном открытии приложения.
- Пауза между порциями ВК настраивается: от 1 до 10 секунд с шагом 1. Изменение применяется со следующей порции. Журнал содержит выбранную паузу, возраст ссылки и факт её изменения при обновлении, чтобы исследовать временные 404.

- В строках сессий видны новые файлы, ошибки и число ещё не скачанных файлов. Одна кнопка меняется по состоянию: продолжить, пауза или повторить. При повторе оценка времени может использовать измеренную скорость прошлого запуска; без статистики причина отсутствия оценки показана явно.
- Кнопки полного списка ошибок и текущих скачиваний доступны без раскрытия аккордеонов. Диалог текущих передач шириной 700 px обновляет строки на месте и сохраняет положение просмотра.
- ВК читает весь список вложений независимо от скачивания, с настраиваемой паузой (по умолчанию 1 секунда) перед каждой следующей порцией. Фото и видео обходятся отдельно, файлы сразу добавляются в очередь со своими лимитами. Общая последовательная очередь API и повторы ограничений ВК могут увеличить интервал; фактической прокрутки нет.
- Таймауты передач и ожиданий в скрытом обработчике проверяются через фоновый таймер. При обновлении просроченной ссылки статус показывает очередь запросов ВК отдельно от самой передачи.
- Только ВК: после HTTP 404 выполняются шесть повторов через 1, 3, 6, 12, 24 и 48 секунд; ожидание данных в каждой повторной попытке равно её задержке. Первая попытка использует настройку ожидания. Оригинал пробуется до перехода к preview; пауза отменяет ожидание. Ожидание повтора освобождает поток; сама передача занимает слот своего типа. Яндекс не получает эти повторы.
- Добавлены лимиты Яндекса 70, 100, 150, 200 и ВК 25+15, 50+30, 70+40, 100+50, 150+70, 200+100. Без сохранённого выбора используются Яндекс 50 и ВК 20+10. Существующие настройки сохраняются.
- Настройки: «Обновить все вкладки ВК», выключенная по умолчанию галочка «Логирование», выгрузка и очистка журнала. Журнал дописывается в ежедневный файл рядом с JSON-базой и содержит: этапы и длительности запросов, ожидания очереди, попытки и HTTP-коды, обновления ссылок, сохранения, паузы и контрольные записи активных операций каждые 30 секунд. В нём нет токенов, ссылок на файлы и текста переписки.

## 1.5.1 — вложенные диалоги и компактный общий блок

- Сессии открываются внутри приложения в диалоге шириной 750 px, ошибки — в диалоге 700 px поверх сессии. На узком экране диалоги уменьшаются без горизонтальной прокрутки. Закрытие ошибок сохраняет раскрытые блоки и прокрутку сессии.
- В диалоге сессии нет блока ввода ссылок. Сохранены текущие передачи, повтор ошибок, повтор с нуля и остальные действия.
- Общие кнопки сокращены и собраны в один ряд. Общий повтор ошибок использует только галочку «Считать preview ошибкой» в блоке «Сессии»; дублирующая галочка удалена.
- Процент и счётчик новых файлов выровнены по правому краю общего блока.

## 1.5.0 — сессии, диагностика и автоматические повторы

- Основной контейнер расширен до 780 px. Вместо селекта и индивидуального блока — обновляемые строки сессий со счётчиками, реальным статусом, кнопками продолжения/повтора и паузы, прогрессом и временем. Паузы сверху, завершённые снизу; названия сокращены до 10 символов, полные доступны в подсказке и отдельном окне. Горизонтальная прокрутка не используется.
- Иконка ↗ открывает индивидуальную сессию: прежние действия, «Повторить с нуля», свёрнутый список всех текущих передач с их статусами, ошибки и пропуски.
- «Открыть все» в общем и индивидуальном списке открывает полный снимок диагностики. Пропуски скрыты по умолчанию; галочка фильтрует снимок без повторного запроса. Ссылки открывают файлы в отдельных окнах, в общем списке показана сессия.
- Ошибки больше не увеличивают процент. Сохранённые оригиналы и копии, а также пропуски учитываются; 80 сохранённых и 20 ошибок дают 80%. Флажки «Считать preview ошибкой» включены по умолчанию.
- «Повторы после завершения» (0–3, по умолчанию 0) справа от «Ожидание данных»: автоматические повторы ошибок и выбранных preview, отдельный счётчик на сессию. Ручной запуск, повтор, пауза и остановка сбрасывают его. При ручной паузе автоповтор отменяется. Повторы идут по сохранённому списку, без нового обхода.

## Обновление 1.4.2: режимы, параллельные загрузки и восстановление ВК

Под ссылкой появился единый список режимов для Яндекс Диска и ВК:

1. **Видео и фото: оригиналы, копии если нет оригинала** — по умолчанию.
2. **Видео и фото: только оригиналы**.
3. **Только фото: оригиналы, копии если нет оригинала**.
4. **Только фото: только оригиналы**.
5. **Только видео**.

У Яндекса первые два режима также сохраняют документы и остальные файлы, как раньше. Режимы «Только фото» и «Только видео» ограничиваются выбранным типом. Копии вместо оригиналов применяются только к фотографиям.

Режим можно изменить во время скачивания: текущие передачи задания отменяются, подходящие файлы автоматически продолжаются, исключённые остаются в базе для последующего включения. Незавершённый файл скачивается заново. Уже сохранённые файлы остаются на диске. Если задание уже завершилось, выберите другой режим и нажмите «Продолжить» или «Продолжить все».

**Старая база при первом открытии получает первый режим для каждого задания**, независимо от прежнего выбора качества. Сохранённые файлы, история и позиции обоих списков не сбрасываются. Новые изменения режима сохраняются отдельно для каждого задания и переживают перезапуск.

Лимит действует **на каждое задание**, а не на все вкладки вместе. У Яндекса — 1, 5, 10 … 50, 70, 100, 150, 200 файлов. У ВК — **1, 4+1, 8+2, 12+4, 20+10, 25+15, 50+30, 70+40, 100+50, 150+70, 200+100** (фото + видео). «1» означает один файл всего. В режиме «Только фото» используется первое число, в режиме «Только видео» — второе; незанятые слоты не передаются другому типу. Изменение лимита применяется ко всем заданиям соответствующего сервиса. При уменьшении уже начатые файлы завершаются, новые ждут свободных слотов.

ВК обходит фото и видео параллельно, с отдельной позицией и порциями по 30 для каждого списка. Следующая порция своего списка запрашивается независимо от загрузки файлов, с настраиваемой паузой (по умолчанию 1 секунда). Запросы к API всех диалогов остаются последовательными с задержкой, даже при большом количестве одновременно скачиваемых файлов.

Для видео достаточно фразы **«Видео от» в названии**, независимо от автора или состава группового чата. Имена участников больше не запрашиваются. Нужен прямой MP4 с разрешённых серверов ВК; YouTube, другие внешние источники, плееры и HLS/DASH пропускаются. Сохраняется максимальное доступное разрешение MP4, а не обязательно исходный файл камеры.

Вкладка ВК должна оставаться открытой на нужном диалоге. Если она выгружена/заморожена, токен истёк или запрос прерван, расширение пытается восстановить её без переключения фокуса и повторяет запрос с той же позиции. Плановых перезагрузок каждые три минуты нет. Автоповторы ограничены: при выходе из аккаунта потребуется войти, при устойчивом отказе доступа будет показана ошибка. Закрытую вкладку или вкладку, переведённую в другой диалог, восстановление не перенаправляет.

Обновите расширение до **1.5.2** на странице управления расширениями.

## Поддержка ВК (1.4.0)

Откройте авторизованный диалог ВК и нажмите значок расширения: ссылка подставится автоматически. Можно вставить ссылку `https://vk.ru/im/convo/101` в расширение — оно найдёт существующую вкладку этого диалога либо откроет её. Дождитесь загрузки диалога; если появится просьба войти, войдите самостоятельно и нажмите «Продолжить».

Фотографии сохраняются в `выбранная папка/vk-messager/Название диалога`, например `vk-messager/Тестовый диалог`. Публичные папки Яндекса по-прежнему сохраняются в `yandex-disk` с исходной структурой. Общая база обоих источников остаётся в `yandex-disk/downloader-state.json`.

Фотографии скачиваются из вложений диалога; видео — согласно выбранному режиму. Оригинал берётся из `orig_photo`; в автоматическом режиме при его отсутствии или неудаче скачивания используется крупнейшее доступное превью (`.preview.jpg` и аналогичные расширения). В режиме «Только оригиналы» ошибка не заменяется превью. Настройка ожидания данных применяется к обоим вариантам. После нескольких неудач ВК всё равно проверяется оригинал каждой следующей фотографии.

Прокрутка не требуется: расширение запрашивает по 30 фото, независимо от скачивания, с настраиваемой паузой (по умолчанию 1 секунда) между порциями. Позиция `cmid + attachment_position` сохраняется после каждой порции. Короткая страница не означает конец; пустая перепроверяется. При временных ошибках выполняются три повтора с задержками, затем задание остаётся доступным для продолжения. При повторяющейся странице завершение не объявляется. Суммарное число найденных фотографий растёт по мере обхода.

Вкладку диалога нужно оставить открытой; попап расширения можно закрыть. Не переключайте эту вкладку на другой диалог — для переписки откройте отдельную. При истечении сессии расширение попробует обновить вкладку автоматически. Если потребуется вход в аккаунт, войдите и нажмите «Продолжить». Расширение не запрашивает у пользователя токен и не сохраняет его. Для первого запуска после изменения разрешений обновите расширение на странице управления расширениями браузера.

Проверено локальными тестами и на предоставленном ответе API без сетевых запросов к ВК. Живая авторизованная проверка выполняется пользователем; интерфейс и внутренний API ВК могут измениться.

В связи с ситуацией вокруг дата-центров особенно важно сохранять локальные копии личного архива. В октябре 2026 года атаки затронули несколько ЦОД Яндекса: после Сасово и Калуги компания сообщила также об атаке на дата-центр во Владимире в ночь на 11 октября ([официальное сообщение, обновлено 11 октября](https://yandex.ru/company/news/09-10-2026-01)). На фоне сбоев часть файлов Яндекс Диска недоступна. В проверенных папках не работает массовое скачивание архивом, а некоторые файлы не удаётся скачать даже по одному. У фотографий иногда остаётся доступное превью, хотя оригинал уже не скачивается: его можно сохранить, но с потерей качества.

Важные фотографии хранятся не только в облачных хранилищах. У многих во вложениях личных диалогов и семейных чатов их может оказаться даже больше: снимки пересылают близким, но не всегда сохраняют отдельно. Поэтому расширение поддерживает и вложения диалогов ВК — чтобы собрать доступные фото и видео на своём компьютере.

**yandex-disk-downloader — временная полумера, чтобы сохранить доступную сейчас часть вашего архива.** Расширение скачивает фотографии, видео, документы и другие файлы по публичной ссылке, само проходит все вложенные папки и сохраняет их структуру на компьютере. Если оригинал фотографии недоступен, оно пробует сохранить копию для просмотра. Восстановить недоступные файлы расширение не может.

Можно вручную запускать скачивание по той же ссылке каждый день: уже сохранённые файлы будут учтены, а вновь доступные — догружены. Если вместо превью появился оригинал, расширение скачает его. Существующие файлы проверяются непосредственно в выбранной папке, даже после переустановки и с пустой историей. Старые preview остаются на месте.

## Как пользоваться

1. На Яндекс Диске выберите каталог, содержимое которого хотите скачать, и создайте для него ссылку через **«Поделиться» → «Скопировать ссылку»**.
2. Откройте полученную ссылку в Chrome.
3. Нажмите значок расширения — жёлтую папку со стрелкой, проверьте ссылку и нажмите **«Скачать всё»**.
4. При первом скачивании сразу откроется системное окно выбора папки. Выберите папку и разрешите доступ. Внутри выбранной папки создаётся **yandex-disk → название каталога**; существующая папка yandex-disk используется повторно.
5. Сменить папку можно через **шестерёнку → Папка скачивания → Изменить папку**. Нажатие этой кнопки останавливает все задания, даже если затем отменить выбор. Продолжить скачивание нужно вручную. Уже скачанные файлы не перемещаются. После смены папки кнопка «Продолжить» скачивает оставшуюся очередь; «Скачать всё» проверяет весь альбом в новом месте.

**Ссылка специально задаёт область действия расширения:** оно обрабатывает выбранный каталог и всё внутри него. Не обязательно создавать ссылку непосредственно на папку с файлами: можно поделиться общей папкой, например «Семейный архив», где внутри находятся годы, события и ещё несколько уровней папок. Расширение само обойдёт их все и сохранит структуру. Отдельные ссылки на каждую подпапку не нужны.

Для нескольких отдельных каталогов создайте ссылки, откройте их в разных вкладках и запустите расширение на каждой. Количество независимых заданий искусственно не ограничено. Список заданий и управление ими доступны в одном всплывающем окне.

Окно расширения размером 600 × 600 можно закрыть: очередь продолжит работать в фоне. Сам Chrome должен оставаться запущенным. После перезапуска браузера откройте расширение и нажмите «Продолжить».

В меню шестерёнки справа сверху есть **«Открыть окно»** — отдельное окно 600 × 600 без панели вкладок — и **«Открыть вкладку»** в текущем обычном окне Chrome. Они показывают ту же очередь и выбранное задание; новые скачивания не создаются.

При наличии задания появляется «Общий прогресс»: общие счётчики и действия. Ниже расположены строки сессий с отдельными кнопками и прогрессом. Общий процент взвешен по числу файлов, ошибки в числитель не входят.

В отдельном окне и вкладке внутри общего блока доступен аккордеон **«Ошибки и пропуски всех заданий»**. В нём показаны все проблемные файлы и папки, полный путь от названия общего каталога и причина. В маленьком окне у значка расширения остаётся список ошибок выбранного задания.

## Что умеет

- Читает все страницы списка, включая альбомы с сотнями и тысячами файлов.
- Сам проходит вложенные папки.
- В каждом задании сначала скачивает фотографии из всех подпапок, затем вторым проходом видео, документы и остальные файлы. Этот порядок действует и при продолжении сохранённой очереди.
- Для ссылки на вложенную папку сохраняет название корневого альбома и весь путь до выбранной папки.
- Скачивает с отдельным лимитом для каждого задания: до 50 файлов Яндекса или до 20 фото + 10 видео ВК. Папка выбирается один раз, без запроса для каждого файла.
- Пробует все типы файлов: фото, видео, документы и другие. Пропускает пустые файлы и ошибки; отсутствие данных в течение выбранного времени (по умолчанию 25 секунд) тоже считается ошибкой.
- У каждого задания есть «Пауза», «Продолжить», «Стоп» и повтор ошибок.
- Сохраняет CSV-отчёт об оригиналах, копиях, пропусках и ошибках.

**Несколько заданий работают независимо, без лимита на число альбомов.** Лимиты задаются в меню шестерёнки отдельно для Яндекса и ВК и применяются к каждому заданию независимо. Для Яндекса доступны лимиты до 200 файлов (по умолчанию 50); для ВК — от 1 до 200+100 фото и видео (по умолчанию 20+10). Увеличение применяется сразу; при уменьшении начатые файлы завершаются, а новые ждут свободного места. В этом же меню можно удалить задание, сохранив скачанные файлы и историю. Оригиналы и preview показаны отдельными счётчиками. Повторный запуск уже активной ссылки открывает существующее задание. Пересекающиеся деревья одного альбома обрабатываются последовательно, чтобы не скачивать одинаковые файлы одновременно.

«Пауза» сохраняет текущее задание для продолжения. «Стоп» завершает его без удаления скачанного; следующий запуск заново читает каталог и сверяется с файлами в выбранной папке.

При новом запуске расширение сначала проверяет файлы по ожидаемому имени и пути внутри выбранной папки / yandex-disk. Если оригинал существует и его размер совпадает с размером на Диске, запросы оригинала и preview не выполняются. Если есть только preview, автоматический режим пробует оригинал; при его недоступности используется существующая копия. Новый preview с номером не создаётся.

Проверка не зависит от базы расширения и истории скачиваний Chrome. При несовпадении размера существующий файл не перезаписывается: расширение показывает ошибку для ручной проверки. Контрольная сумма существующего файла заново не вычисляется; совпадение имени и размера не гарантирует одинаковое содержимое. Файлы в других папках и ранее созданные копии с добавленным номером не переименовываются и не удаляются.

### Одинаковые файлы и повторное скачивание

Флажок **«Скачивать все без проверки дублей» включён по умолчанию**. Если в одной папке Яндекс Диска лежат два одинаковых файла под разными именами, будут сохранены оба. Подсказка при наведении на флажок напоминает об этом.

Если снять флажок, расширение сравнит контрольные суммы SHA-256, полученные от Яндекса, и сохранит одну копию одинаковых файлов внутри каждой папки. В разных папках копии сохраняются отдельно. Если надёжной контрольной суммы нет, файл скачивается. Настройка применяется при нажатии «Скачать всё» и не удаляет уже скачанные дубли.

**Защита от повторного скачивания одного и того же уже сохранённого файла работает при любом положении флажка.** Если сначала скачали без дублей, а потом включили флажок и запустили каталог заново, расширение догрузит пропущенные экземпляры.

## Папки создаются автоматически

Например, ссылка на «Семейный альбом → 0 лет → Выписка → retouch» сохранится так:

```text
Выбранная папка/
└── yandex-disk/
    └── Семейный альбом/
        └── 0 лет/
            └── Выписка/
                └── retouch/
                    ├── DSC_0001.JPG
                    └── DSC_0002.preview.jpg
```

Путь берётся из публичной ссылки, название альбома — из данных Яндекс Диска. Открывать каждую папку вручную не нужно. При запуске из корня будут обработаны все подпапки; при запуске из вложенной папки — только она и её содержимое.

Используется папка, выбранная в расширении. Для прежних загрузок выбирайте родительскую папку существующей yandex-disk. Недопустимые символы в названиях заменяются. Файлы пишутся напрямую в выбранную папку и не появляются в списке скачиваний Chrome; прогресс виден в расширении. Существующие файлы не перезаписываются и копии с номером не создаются.

## Оригиналы и копии

| Режим | Что сохраняется |
| --- | --- |
| Оригиналы с заменой недоступных фото копиями | Сначала оригинал. При ошибке фото — копия для просмотра. После трёх последовательных ошибок оригиналов остальные фото загружаются копиями. При новом запуске для уже сохранённых превью оригинал проверяется снова. |
| Только оригиналы | Только исходные файлы. Недоступные оригиналы попадут в ошибки. |

Настройка копий относится только к фотографиям. Видео, документы и остальные файлы всегда скачиваются в оригинале.

Копии отмечены **`.preview`** в имени. Их разрешение, качество и метаданные могут отличаться от исходника. Расширение не восстанавливает недоступные оригиналы и не включает отключённое Яндексом скачивание ZIP.

Запрос списка или ссылки на файл ждёт до 20 секунд. Передача прерывается после выбранного времени **без поступления данных** (по умолчанию 25 секунд); это не ограничение общей длительности скачивания. Большое видео может скачиваться много минут, пока данные поступают. В окне видны этап ожидания и объём файла. «Пауза» и «Стоп» прерывают передачу; незавершённый файл при продолжении скачивается заново. При ответе 429 очередь приостанавливается — продолжите позже.

## Ограничения

Поддерживаются публичные ссылки вида `https://disk.yandex.ru/d/…`, `/i/…` и `yadi.sk`, включая вложенные пути. Личный раздел `/client/disk`, закрытые и защищённые паролем папки не поддерживаются.

Обычные изображения проверяются декодированием. Оригиналы фото дополнительно проверяются по размеру и SHA-256, когда он предоставлен Яндексом. Для RAW, TIFF и HEIC полноценное декодирование в Chrome не гарантируется — остаются проверки размера и контрольной суммы. Максимум 512 МБ на фотографию, обрабатываемую в памяти.

Видео, документы и другие файлы записываются потоком непосредственно в выбранную папку, без загрузки всего файла в память. Перед завершением записи проверяется размер, известный Яндексу. При ошибке или отмене незавершённая запись отбрасывается. Ранее существующие файлы не удаляются.

Во время сканирования желательно не менять содержимое альбома: перемещение файлов может сдвинуть страницы списка. Очень длинные пути могут не сохраниться из-за ограничений операционной системы.

## Доступ и личные данные

Расширение не требует пароль Яндекса, не читает cookies и не отправляет фотографии сторонним сервисам. Оно обращается к API и файловым серверам Яндекса по указанной публичной ссылке. Задания, история загрузок, пути файлов и результаты хранятся локально в браузере.

Разрешения:

| Разрешение | Для чего |
| --- | --- |
| Загрузки | Восстанавливать состояние незавершённых загрузок старых версий |
| Доступ к выбранной папке | Проверять существующие файлы и сохранять новые внутри yandex-disk; запрашивается при выборе папки |
| power и alarms | Предотвращать автоматический сон при активной очереди и проверять фоновый обработчик |
| Активная вкладка | Подставлять публичную ссылку при нажатии значка расширения |
| Фоновый документ | Проверять изображения и продолжать очередь после закрытия всплывающего окна |
| Серверы Яндекса | Получать список файлов, оригиналы и копии |

[Подробнее о данных](PRIVACY.md).

## Разработка и сборка

Само расширение работает без установки библиотек и без сборки. Его файлы находятся в `extension/`.

Для тестов нужен Node.js 22 или новее:

```sh
npm test
```

Для ZIP нужен Python 3:

```sh
python scripts/build.py
```

Архив появится в `dist/yandex-disk-downloader.zip`. Папка `dist` и ZIP исключены из Git. В GitHub Actions проверка запускается для ветки `main` и pull request. При отправке новой версии в `main` либо ручном запуске Release создаётся релиз с архивом. Уже выпущенная версия автоматически не перезаписывается. **ZIP публикуется только в Releases, не в исходниках.**

Проверки охватывают пагинацию более 500 файлов, вложенные пути, обход подпапок, независимость очереди от окна, паузу/продолжение, восстановление сохранения, повреждённые изображения, размер/хеш и ограничения API. [Статус проверок](docs/verification.md).


## Общее управление и сохранённая папка (1.3.3)

В общем прогрессе при нескольких заданиях появляются «Продолжить все» для остановленных и приостановленных незавершённых заданий и «Остановить все» для работающих и ожидающих запуска. Если есть оба вида заданий, доступны обе кнопки. Общая остановка сохраняет прогресс; продолжение обрабатывает оставшуюся очередь, не обходит весь архив заново и не запускает завершённые задания. Незавершённый текущий файл скачивается заново. Повтор ошибок, ожидавший запуска, сохраняет свой режим, включая выбранный повтор preview.

При первом скачивании открывается только системный диалог выбора папки. При обновлении или повторном открытии окна расширения папка загружается из сохранённых данных. Если разрешение ещё действует, подтверждать её не нужно. Если Chrome потребует разрешение снова, расширение запрашивает доступ к уже сохранённой папке. В предложении Chrome выбирайте «Разрешать при каждом посещении», если такой вариант доступен; отменённое или отозванное разрешение расширение не может восстановить без вашего участия. [Описание постоянных разрешений Chrome](https://developer.chrome.com/blog/persistent-permissions-for-the-file-system-access-api).


## Общие действия и настройки (1.3.4)

В общем прогрессе для завершённых заданий доступна кнопка «Повторить всё»: повторно прочитать каталоги и скачать недостающее с проверкой существующих файлов. «Повторить все ошибки» использует сохранённые списки завершённых заданий; общий флажок «Считать preview ошибкой» добавляет попытки получить оригиналы вместо копий. Остановленные и работающие задания этими кнопками не перезапускаются.

Количество одновременных скачиваний и ожидание данных расположены в настройках рядом, по половине строки. Ожидание: 5, 15, 25, 40, 60, 120 или 240 секунд; по умолчанию 25. Выбор сохраняется и действует для следующих файлов. Лимит одновременных скачиваний меняется сразу.


## Расположение блоков (1.3.5)

Блок ссылки расположен первым под шапкой. Общий прогресс и строки сессий доступны и для одного задания. Индивидуальные сведения открываются отдельным окном по иконке ↗.

Карточка «Загрузка — название страницы» при нескольких заданиях по умолчанию свёрнута, её можно раскрыть нажатием на заголовок. При одном задании она всегда открыта и не сворачивается. Отдельный крупный заголовок альбома убран.


## Блок ссылки (1.3.6)

Блок ссылки сворачивается. Он открыт по умолчанию, если ссылка подходит для скачивания. Ручное сворачивание сохраняется при обновлении прогресса.


## Переносимая база (1.3.7)

Задания, прогресс, ошибки, preview, история сохранённых файлов и настройки теперь сохраняются в yandex-disk/downloader-state.json. После переустановки выберите прежнюю родительскую папку: задания восстановятся без автоматического запуска. В JSON отдельно указаны версия расширения и версия формата. Перед преобразованием старой структуры создаётся резервная копия; повреждённый или неизвестный новый формат не перезаписывается.

Обновите установленное расширение в его прежней папке и один раз откройте его с доступом к папке скачивания: существующая база Chrome будет перенесена в JSON, если файла ещё нет. Перед удалением старой установки убедитесь, что downloader-state.json появился. Уже удалённую до этого базу Chrome восстановить из файлов фотографий нельзя.

При выборе другой папки существующая JSON-база этой папки заменяет список заданий в интерфейсе. Если JSON нет, в новую папку переносится текущий список остановленных заданий. Фотографии не перемещаются. Папку скачивания и JSON можно скопировать на другой компьютер и выбрать там её родительскую папку. Браузер всё равно должен разрешить доступ к этой папке.

Сохраняется текущая очередь и история файлов, а не бесконечный журнал каждого нажатия. Запись JSON фиксируется после контрольных точек очереди, изменения настроек и удаления задания. При аварийном завершении восстанавливается последняя полностью сохранённая точка; наличие файлов проверяется отдельно.


## Общие кнопки (1.3.8)

Общий блок использует те же размеры и оформление кнопок, что и отдельная загрузка: «Продолжить все», «Приостановить все», «Остановить все», «Повторить все ошибки» с флажком preview и «Отчёт по всем». Недоступные действия остаются видны, но неактивны. Отдельная кнопка «Повторить всё» заново проверяет завершённые альбомы; существующие файлы не дублируются.

Общая пауза сохраняет место и ожидавший повтор ошибок. «Отчёт по всем» доступен после паузы или завершения всех заданий и сохраняет один CSV в yandex-disk с названием альбома и публичной ссылкой для каждой строки.


## Новые файлы за запуск (1.3.9)

В карточке выбранной загрузки вместо режима качества показан процент обработки её файлов. Рядом зелёная метка «Новых: N» считает только реально сохранённые оригиналы и preview за текущий запуск, включая получение оригинала вместо preview. Уже существующие файлы, пропуски и неудачные загрузки не увеличивают счётчик. Новый обход или повтор ошибок сбрасывает его; пауза, продолжение и повторное открытие интерфейса сохраняют.

Процент считается так же, как общий: обработанные файлы, включая ошибки и пропуски, делятся на количество найденных файлов выбранного задания. Поэтому 100% означает завершение обработки, а не отсутствие ошибок. Метка «Новых» показывает только новые записи на диск в этом запуске.


Зелёная метка «Новых» у общего прогресса считает новые записи после последнего общего повтора. «Повторить всё» и «Повторить все ошибки» начинают отсчёт с нуля: старые результаты других заданий не добавляются. Уже работающие задания продолжаются; в общий счётчик попадают только их последующие сохранения. Их отдельные счётчики сохраняют результат всего своего запуска. Пауза, продолжение и восстановление JSON-базы сохраняют оба счётчика. Повтор отдельного задания обнуляет только его счётчик и вклад в общий результат.

### Интерфейс 1.4.1

В настройках и строках сессий задания помечены [YD] / [VK]. Кнопки «Окно» и «Вкладка» находятся в основной шапке слева от шестерёнки. При подходящей ссылке блок ввода открыт по умолчанию, если такого задания ещё нет; ручное сворачивание сохраняется при обновлении прогресса. Обычная ссылка ВК преобразуется в общую панель вложений: https://vk.ru/im/convo/101?rp=peer101 — из неё скачиваются фото и выбранные видео.

### Время и прогресс (1.4.2)

В общем блоке и карточке задания показаны полоса прогресса, активное время без пауз и приблизительная оценка оставшегося времени. Общее активное время не складывает пересекающиеся периоды разных заданий. Оценка строится после нескольких сохранений по средней скорости обработки файлов; большие видео могут заметно её менять. Пока ВК выдаёт список порциями, оценка подписана как время на уже найденные файлы, а процент не достигает 100% до конца выбранных списков. Время до установки этой версии восстановить нельзя: отсчёт начинается при следующем запуске.

В строке сессии «Скачано» включает оригиналы и копии; число копий дополнительно показано отдельно. Ошибки и пропуски доступны в индивидуальном окне и общей диагностике.
